Part 1 - the ideas (2 of 8)

Context and tokens

Context

Everything Claude can see right now: the files it read, your messages, its own replies. It starts empty every session.

Tokens

The unit it reads and writes in - roughly three quarters of a word. You pay per token, in and out.

Run /context any time - this is live, not a guess.

A full Salesforce repo does not fit in the window. What goes in decides what comes out.

Part 1 - the ideas (3 of 8)

CLAUDE.md: instructions read every session

# CLAUDE.md - repo root, plain markdown
Project: C360 person-account service (Apex, Flows, LWC)

## Commands
Deploy:  sf project deploy start --source-dir force-app
Test:    sf apex run test --wait 10

## Standards
- Service classes end in Service. Tests end in Test.
- No SOQL or DML inside loops. Check CRUD/FLS.
- Done = deployed, tests green, analyzer clean.
  • Claude reads it before you type a word.
  • Only what is always true: commands, standards, naming.
  • /init writes the first draft - then you trim it.
Part 1 - the ideas (4 of 8)

Rules: detail that loads only when it matters

# .claude/rules/apex.md
---
paths: ["**/*.cls", "**/*.trigger"]
---
- Bulkify everything: collections in, collections out.
- One trigger per object, logic in a handler class.
- Tests need real assertions, wrapped in
  Test.startTest() / Test.stopTest().
  • CLAUDE.md is always on. Rules load only for matching files.
  • Editing a Flow? The Apex rules never load. No tokens, no noise.
  • This is where the depth lives: bulkification, CRUD/FLS, sharing.

---
name: apex-review
description: Check edited Apex against
  our standards
---
1. Read the diff. Flag SOQL/DML in loops.
2. Check CRUD/FLS on every query.
3. Tests must assert behavior.

Hooks: scripts that run on Claude's actions

# .claude/settings.json
"hooks": {
  "PreToolUse": [{
    "matcher": "Bash",
    "hooks": [{
      "type": "command",
      "command": ".claude/hooks/deny-dangerous-sf.sh"
    }]
  }]
}
● Bash: sf org delete scratch --target-org prod
  ✗ Blocked by hook: destructive sf commands
  need a human

Nobody typed a review. The hook fired
on its own.
  • CLAUDE.md advises. A hook enforces - it cannot be talked round.
  • Fires automatically: before a tool call, after an edit, on stop.

Keep the context clean

  • Send wide reading to a subagent; keep only the summary.

Part 4 - working well (4 of 5)

Where the tokens go

  • Path-scoped rules. Apex rules never load while you edit a Flow.
  • A lean CLAUDE.md. Every line loads into every session - each one is rent.
  • The right model. Haiku for grunt work, Opus only when the task earns it.
  • Subagents. The wide reading happens in their window, not yours.
Part 4 - the ground rules

The rules when Claude writes our code

  • You review everything you merge. Your name is on the commit.
  • Same bar as human code. Tests real, scanners clean, no skipped findings.
  • No secrets, ever. No credentials or customer data in prompts or setup files.
  • Production stays human. Claude never deploys there.
