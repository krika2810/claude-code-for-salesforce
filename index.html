Why we are doing this

Repo instructions prevent common Apex mistakes

  • Without repo instructions, Claude can repeat the same mistakes we catch in review.
// without repo instructions
for (Account a : accounts) {
    List<Contact> cs = [SELECT Id FROM Contact
        WHERE AccountId = :a.Id]; // SOQL in a loop
    update cs; // DML in a loop too
}
// same prompt, with our repo instructions
Map<Id, Account> byId = new Map<Id, Account>(accounts);
List<Contact> cs = [SELECT Id, AccountId FROM Contact
    WHERE AccountId IN :byId.keySet()]; // one query
update cs; // one DML

Same prompt. Repo instructions change the result.

Part 1 - the ideas (3 of 8)

Put shared instructions in CLAUDE.md

# CLAUDE.md - repo root, plain markdown
Project: C360 person-account service (Apex, Flows, LWC)

## Commands
Deploy:  sf project deploy start --source-dir force-app
Test:    sf apex run test --wait 10

## Standards
- Service classes end in Service. Tests end in Test.
- No SOQL or DML inside loops. Check CRUD/FLS.
- Done = deployed, tests green, analyzer clean.
  • Claude reads it at the start of each session.
  • Keep only shared commands, standards, and naming rules here.
  • /init creates a first draft. Review it and remove anything unnecessary.
Part 1 - the ideas (4 of 8)

Use rules for specific file types

# .claude/rules/apex.md
---
paths: ["**/*.cls", "**/*.trigger"]
---
- Bulkify everything: collections in, collections out.
- One trigger per object, logic in a handler class.
- Tests need real assertions, wrapped in
  Test.startTest() / Test.stopTest().
  • Claude loads a rule only when it works on a matching file.
  • When you edit a Flow, the Apex rules do not load.
  • Put detailed guidance here: bulkification, CRUD/FLS, and sharing.

Part 1 - the ideas (6 of 8)

Use hooks to block unsafe commands

# .claude/settings.json
"hooks": {
  "PreToolUse": [{
    "matcher": "Bash",
    "hooks": [{
      "type": "command",
      "command": ".claude/hooks/deny-dangerous-sf.sh"
    }]
  }]
}
● Bash: sf org delete scratch --target-org prod
  ✗ Blocked by hook: destructive sf commands
  need a human

The hook checks the command before it runs.
  • CLAUDE.md gives instructions. A hook can stop a command.
  • Hooks can run before a command, after an edit, or when Claude stops.

Part 4 - working well (4 of 5)

Reduce token use

  • Use path-scoped rules. Apex rules do not load while you edit a Flow.
  • Keep CLAUDE.md short. Every line loads into every session.
  • Choose the right model. Use smaller models for simple work.
  • Use subagents. They can read many files and return a short summary.
Part 4 - the ground rules

Review and protect every change

  • You review everything you merge. Your name is on the commit.
  • Use the same checks as human-written code. Run tests and fix analyzer findings.
  • No secrets, ever. No credentials or customer data in prompts or setup files.
  • Keep production deployment manual. A developer approves and runs it.
