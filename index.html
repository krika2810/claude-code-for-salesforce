Act E — Context

Context fills → performance degrades

Claude's context window fills up fast, and performance degrades as it fills. — Anthropic best practices

Name it: context rot — old files, failed attempts, and unrelated tasks still in the window, so the next answer drifts.

Scratchpad that gets messy  →  /clear = new notepad
(one metaphor — don't stack more)
Act E — Context

What enters context

Startup junk + every file you touched + every command you ran.

  • Work: file reads, command output, tool results, your prompts, Claude's replies
  • Path-scoped rules: when matching files are touched

Act E — Context

Token-saving playbook (Salesforce edition)

Eight habits. Pick three for your team this week.

  • CLAUDE.md under ~200 lines; Apex detail → .claude/rules/apex.md
  • Path-scoped rules so Flow work doesn't load LWC essays
  • Skills for long procedures (/apex-review, /deploy-validate) — on demand
  • Subagents for "find all trigger handlers"
  • Models: Haiku scans · Sonnet daily Apex/LWC · Opus nasty governors
  • Prefer CLI (sf, gh) over huge JSON in chat / unnecessary MCP
  • Two failed corrections → /clear + better prompt
  • Never "read the whole repo"

Add Compact instructions in CLAUDE.md so /compact preserves org alias, test failure messages/IDs, deploy/validation IDs, and files changed.

Act G — Verify

Verification loop + prod guards

Implement → sf apex run test → sf code-analyzer run → read failures → fix → repeat
Stop only when checks pass. Paste evidence — don't claim "done."
LayerWhat it does
Prompt Don'tsAdvisory
.claude/settings.json denyBlocks dangerous tool calls
PreToolUse / PostToolUse hooksDeterministic scan / block prod deploy
Human mergeSame bar as human-written code

⚠️ Checkpoints snapshot files before edits — they do not undo org deploys. Prod/deploy guards belong in hooks + permissions, not only CLAUDE.md prose.

Act G — Verify

Do / Don't

Do

Name class, error, expected behavior, verification command
Plan mode for multi-file refactors
/clear between unrelated tasks
Review every diff; run org tests
Commit CLAUDE.md so learning compounds

Don't

Kitchen-sink sessions (Flow + CI + architecture in one chat)
Paste secrets, customer data, or session IDs
Let Claude deploy production unattended
Bloated CLAUDE.md that burns tokens
Correct the same failure more than twice without clearing
Treat volume of generated metadata as finished work
